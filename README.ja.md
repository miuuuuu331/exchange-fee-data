# 取引所手数料データセット

主要暗号資産取引所 7 社の手数料を構造化したオープンデータセットです。現物と無期限先物、メイカーとテイカー。現在は VIP0 を収録しており、上位ティアは順次追加中です。毎週水曜に人手で再検証し、各週のスナップショットはすべて `data/history/` に保存しています。

JSON と CSV で提供。MIT ライセンス。API キー不要、レート制限なし、登録不要 — git リポジトリの中のただのファイルです。

---

## なぜ作ったか

どの取引所も手数料表を公開していますが、公開の仕方は各社バラバラです。表にまとめている所もあれば、ヘルプセンターの記事に埋もれている所もあり、ログインしないと自分の実際のティアが表示されない所もあります。ティア名は変わり、キャンペーン料率は告知なく終了し、過去の数字を残している所はどこにもありません。

その結果、**「Bybit の先物テイカー手数料は 3 月時点でいくらだったか」** という基本的な問いすら、現状どこにも答えがありません。

そこで週に一度、全取引所を同一スキーマでスナップショットしています。

### スキーマ

```json
{
  "snapshot_date": "2026-08-05",
  "exchanges": [
    {
      "id": "binance",
      "name": "Binance",
      "source_url": "https://www.binance.com/ja/fee/schedule",
      "verified_at": "2026-08-05",
      "spot":    { "vip0": { "maker": 0.0010, "taker": 0.0010 } },
      "futures": { "vip0": { "maker": 0.0002, "taker": 0.0005 } },
      "notes": "BNB 保有で現物手数料が 25% 割引。"
    }
  ]
}
```

料率はすべてパーセントでも bps でもなく **小数** です。`0.0005` は 0.05% を意味します。手数料データを扱う際に最も間違いやすい箇所なので、スキーマで強制しています。

CSV のカラム：`snapshot_date, exchange_id, market, tier, maker, taker`。

## 検証方法

毎週水曜、各取引所の公開手数料ページを人手で開いて確認し、アフィリエイト管理画面の数値と突き合わせます。管理画面のほうが公開ページより先に更新されていることが多いためです。両者が食い違う場合は、どちらかを勝手に採用せず `notes` に記録します。

突合手順の全体 — 何をひとつのティアとみなすか、キャンペーン料率をどう扱うか、週の途中で料率が変わったらどうするか — は [RAILSDESK の評価基準](https://railsdesk.com/ja/#method) に記載しています。

クロールは行っていません。多くの取引所がティア情報をクライアントサイドでレンダリングし、アカウント状態によって出し分けているため、手数料ページのクロールは正しいデータより誤ったデータを生む頻度のほうが高いからです。

## 表示手数料と実効手数料

このデータセットで取引所を比較する場合、先に一点だけ断っておきます。**ここにある数字は表示手数料** であり、受けられる可能性のある割引を一切適用する前の定価です。

実際の負担額は、通常この三つによって書き換えられます。

1. **出来高ティア** — 現時点で VIP0 を収録、VIP1 以上は追加作業中です。
2. **取引所トークン割引** — 例えば BNB を保有すると Binance の現物手数料が 25% 引きになります。料率フィールドではなく `notes` に記載します。
3. **紹介経由のキャッシュバック** — 紹介関係を通じて支払手数料の一部がトレーダーに戻る仕組みです。本データセットには一切含まれません。取引所の手数料表ではなく、そのアカウントがどのリンク経由で開設されたかに依存する値だからです。

三つのうち金額が最も大きいのはたいてい三番目で、公開資料が最も乏しいのも三番目です。取引所ごとの現行還元率は [取引所手数料キャッシュバック](https://railsdesk.com/ja/) で別途管理しており、精算条件を項目別に比較した内容は [分析記事](https://railsdesk.com/ja/articles/) にあります。

コストモデルを組むなら、この三つは独立した乗数として扱うことをおすすめします。ひとつの `fee` フィールドにまとめてしまうことが、バックテスト結果が実態より良く出る典型的な原因です。

## コントリビュート

訂正の指摘を歓迎します。このリポジトリを公開している主な理由でもあります。

1. フォークして `data/fees.json` を編集
2. `python scripts/validate.py` を実行 — スキーマ検証と異常な料率の検出を行います
3. 根拠となる取引所の手数料ページ URL を添えて PR を作成

取引所の追加リクエストは、手数料ページの URL を添えて issue へ。基準は、公開されており機械可読な手数料ドキュメントがあり、かつ有意な出来高があることです。
